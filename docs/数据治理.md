# 数据治理规范（2026-10-29 起生效）

> 回应三个诉求：① 策略可扩展、按策略推荐；② 推荐存储支撑后验校验→反哺策略；
> ③ **数据修改只有一个入口**。本文是唯一契约文档，改表/加策略先读这里。

---

## 一、单写入口契约（硬约束，有测试保障）

- **所有 INSERT / UPDATE / DELETE 只允许出现在 `src/mcp_eastmoney/data/db.py`**。
  - 数据客户端（data/*_client.py）只负责"拉"，不落库；
  - 计算层（compute/）纯函数零 IO；
  - 编排层（refresh.py）与服务层（server.py）只调用 `db.upsert_* / insert_*` 系列函数；
  - 其他模块可以用 `db._conn()` **读**，但不得写。
- **保障机制**：`tests/test_data_governance.py::test_single_write_entry_db_only`
  扫描全部源码，任何绕过 db.py 的写 SQL 会让测试挂——CI/本地跑测试即拦截。
- 读数据建议走 `db.query_*` 系列而不是裸 SQL，方便统一缓存与列变更。

## 二、Schema 演进：版本化迁移（唯一入口 `db.init_db()`）

- 版本号存 `PRAGMA user_version`，当前 `SCHEMA_VERSION = 5`。
- 加列/加表流程：**只在 `db.py` 的 `DDL`（新库）+ `_migrate()`（老库）两处同时改**，
  bump `SCHEMA_VERSION`，跑 `uv run python -m mcp_eastmoney.refresh dbinfo`
  或任何工具触发 `init_db()` 即自动迁移。禁止在业务代码里散落 `ALTER TABLE`。
- v2 内容（2026-10-29）：`strategies` 注册表、`recommendations.strategy_def`
  参数快照列、`recommendation_reviews.alpha_pct` 超额列。
- v3 内容（2026-10-30）：**market_snapshot 表退役**——`total_mv/float_mv` 并入
  `quotes_daily`，全市场截面改为由 `quotes_daily` 最新交易日**派生查询**
  （量比/振幅现算，市值取摄入列）。quotes_daily 成为唯一真相源。
- v5 内容（2026-10-30）：**`chip_daily` 删除**——筹码由 `quotes_daily` 现算，
  落库缓存与真相源重复且无消费者。
- v4 内容（2026-10-30）：**`sector_flow` 板块资金流表**（行业 + 概念同表，
  `sector_type` 区分）：主力/超大/大/中/小单净额与占比、领涨股，eod 每日落库，
  支撑主线判断（`get_sector_flow`）。

## 三、策略怎么加（推荐主路径）

1. 在 `data/strategies/` 放一个 YAML（同名可覆盖包内置 `src/.../recommend/strategies/`）：

```yaml
name: my_strategy            # 唯一；save_recommendation 的 skill_version 必须用它
version: "1.0"               # 改参数时 bump，注册表留档
display_name: 我的策略
description: 一句话
style: 低吸                    # 打板/低吸/趋势/事件驱动
market_regime: neutral         # risk_on/neutral/risk_off/rotation
hard_filters:                  # market_snapshot 截面硬过滤
  amount_min: 300000000
  change_pct_min: -2
factor_weights:                # 横截面分位打分
  momentum_20: 0.4
  turnover_rate: 0.2
```

2. 无需注册动作：`list_strategies / screen / run_pipeline` 每次加载 YAML 并
   **自动同步进 `strategies` 注册表**（definition 存完整 JSON）。
3. 推荐时 `save_recommendation(skill_version=my_strategy)`：系统自动把
   **当时的完整参数快照**写入 `recommendations.strategy_def`——之后改 YAML
   不影响历史归因，可对比"参数版本 A vs B"的胜率。

## 四、推荐 → 后验 → 反哺策略（证据链字段）

```
recommendations（一单一次决策）
  rec_date / code / thesis / style / confidence
  skill_version → strategies.name（归因分组键）
  strategy_def → 推荐时刻参数 JSON 快照（精确到参数版本）
  status: open / final
recommendation_reviews（eod 每日自动写）
  pnl_pct / max_gain_pct / max_drawdown_pct / hit_target（终评）
  alpha_pct → 同期相对上证超额（v2 起落库；市场涨跌中区分运气与能力）
screen_runs（每次 screen/run_pipeline 存档）
  universe/filtered/result JSON → 复盘漏斗健康度
```

反哺查询：
- `get_recommendation_stats(action=stats, group_by=skill_version)` → 各策略胜率/平均盈亏/**平均超额**；
- `get_decision_history(code)` → 同票历史决策 + 教训回注；
- 参数版本对比：`strategy_def` 与 `strategies.definition` 逐单比对（SQL 即可）。
- 防跑偏：一组 <5 条终评样本不下结论（stats 的 `reliable` 字段）。

## 五、表清单与"留/删"判定（2026-10-30 整理，v5 后共 19 张）

### 证据类——永不删（决策与归因的档案）
`screen_runs`（漏斗存档）· `recommendations`（含参数快照）· `recommendation_reviews`（含 α）· `zt_pool`（情绪历史）· `lhb_daily` · `earnings_forecast` · `strategies`（注册表）· `watchlist`

### 时序类——保留全量（策略与后验的原料）
`stock_basic` / `stock_industry`（周更）· `quotes_daily`（**唯一真相源**：日K+估值+市值，
截面由它派生；后续全量回填）· `sector_flow`（板块资金流，eod 每日）· `index_daily`（时间基准）· `concepts` / `stock_concepts`（概念 diff 需历史）· `financial_indicators`（待全量回填）· `news`
> `market_snapshot` 已于 v3 退役；截面 = `db.query_market_snapshot()`（quotes_daily 最新日派生）。

### 概念成分数据源（v6.1，2026-10-30）
- **源：东财板块体系**（`m:90 t:3` 概念清单 + `fs=b:BKxxxx` 全量成分），
  与 `sector_flow` 同码（BKxxxx），可直接 join 做“板块资金流 × 成分股”。
- 弃用同花顺：无 cookie 只能解析首页 Top10；带 cookie 翻页会 401（hexin-v 风控）。
- 抓取纪律：0.35s/板块限速；**断点续跑**（当日已落库的概念跳过）；
  连续 6 个板块失败自动中止（东财限流），稍后重跑即续传。
- 命令：`uv run python -m mcp_eastmoney.refresh concepts`

### 可再生类——eod 末步 prune 自动瘦身
| 表 | 保留 | 可删部分 | 理由 |
|---|---|---|---|
| `fetch_log` | 近 **30** 天 | 旧审计行 | 补跑自查只需近期 |
| `quotes_15min` | 近 **30** 天 | 旧分时 | 只服务盘中，盘后无回看价值 |

手动执行：`uv run python -m mcp_eastmoney.refresh prune`（eod 第 16 步自动跑）。

## 六、既有约束提醒

- 写库一律幂等（INSERT OR REPLACE），eod 可安全重跑；
- `market_snapshot` 日期标签为 point-in-time 语义（盘前刷新打 T-1 标签）；
- 作废单（无法入场）写 `days_held=0` 行，stats 已排除。
